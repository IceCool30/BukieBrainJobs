# BW-003 Architecture Contract

**Document ID:** BW-003-ARCH  
**Version:** 1.0  
**Status:** Approved Architecture Draft

## 1. Objective

Keep BW-003 transport-agnostic and replaceable. UI depends on an `IBrainWorkerLeadsRepository` contract. Business rules remain outside presentation components.

Phase 1 may use deterministic in-memory/localStorage data, while preserving a future authoritative API/realtime adapter boundary.

## 2. Core Contracts

Provider gate:

`authenticated && role === 'brainworker' && isBrainWorkerApproved && operationalProfile.isComplete`

The repository independently enforces this gate. Route guards are not the sole security boundary.

Lead projection minimum:

- `id`
- `jobId`
- `invitationId`
- `title`
- `description`
- `serviceId`
- `categoryId`
- `cityId`
- `neighbourhoodOrZone`
- optional `landmark`
- `urgency`
- `scheduledStartAt`
- optional `scheduledEndAt`
- optional `estimatedHours`
- pricing mode and permitted pricing data
- authorized attachment references
- invitation timing/state

## 6. Matching Boundary

BW-003 consumes an authoritative eligibility projection. BW-002 `getMatchingHydrationProfile(brainWorkerId)` remains the bridge for service, schedule and coverage information.

Eligibility must use:

- active configured service to platform skill/category mapping;
- verified onboarding city ownership;
- BW-002 primary city;
- operational zones;
- configured travel radius;
- lossless seven-day schedule;
- duty/readiness state.

The existing legacy single-window matching fields must not be fabricated from the weekly schedule.

BW-003 does not change global matching weights merely to render the inbox.

## 7. Invitation Boundary

Repository mutations verify provider identity, approval, invitation ownership, job/invitation compatibility, and unresponded state.

`respondedAt` is generated by mutation authority.

Accept uses the existing canonical job transition machinery. Decline records an invitation response without creating a fictional DECLINED job status.

## 8. Quotation Boundary

Quotation is independent from booking confirmation, payment authorization, escrow, and payout.

Diagnostic fee comes from the active provider catalog. BW-003 does not decide later credit, refund, or settlement treatment.

Quote totals use integer kobo arithmetic. Client-submitted totals that conflict with derived line items are rejected.

## 9. Realtime Boundary

The repository may expose `subscribe` for reactive updates. Transport is intentionally unspecified. Existing socket infrastructure, polling, server events, or another approved transport may implement it later.

The UI must not call local refreshes realtime without an authoritative update.

## 10. Offline Boundary

Cached reads are tenant-scoped by BrainWorker ID. Mutation methods fail closed while offline. No offline mutation queue is introduced.

## 11. Testing Boundary

Production code belongs under the BrainWorker leads production boundary. Testing helpers remain physically separated under a `testing/` subtree. Production modules must contain zero imports from `testing/`.

## 12. Route Security

`/brainworker/leads` follows the established route pattern:

1. retrieve authenticated session;
2. redirect unauthenticated user to login with return path;
3. fail closed for non-BrainWorker role;
4. redirect unapproved provider to verification status;
5. block incomplete operational profiles from lead queries;
6. bind repository operations to the authenticated BrainWorker ID.

The repository repeats authorization independently.

## 13. Architectural Invariants

- One authoritative provider identity.
- One authoritative service-to-skill mapping.
- One authoritative coverage/readiness model.
- No private customer contact data before confirmation.
- No client-authored response timestamps.
- No client-authored authoritative quote totals.
- No payment/escrow coupling.
- No matching-engine rewrite.
- No testing imports in production.
