# BukieBrainJobs Design Canonicalization

Status: Canonical guidance
Version: 1.0

## Purpose

`DESIGN.md` is retained as the supplied visual source because it contains the approved visual tokens, typography, spacing, layout, shape, elevation and component direction.

The supplied file also contains legacy product-language references from the design-source generation context. Those references are not BukieBrainJobs product requirements.

## Authority boundary

Use `DESIGN.md` for:

- Brand colors and semantic color relationships
- Typography
- Grid and layout
- Spacing
- Radius and shape language
- Elevation and depth
- Component visual direction
- Accessibility-oriented visual constraints

Use approved BukieBrainJobs product specifications for:

- Product naming
- User roles
- Marketplace terminology
- Calls to action
- User journeys
- Product claims
- Trust messaging
- Feature behavior

## BukieBrainJobs terminology

The following product terms are canonical for BukieBrainJobs:

| Legacy source language | BukieBrainJobs meaning |
| --- | --- |
| Candidate | BrainWorker, where the context refers to the service professional |
| Employer / recruiter | Customer or business customer, depending on the approved feature specification |
| Apply Now | Book a Service, Request Service, or another approved action for the relevant flow |
| Job opportunity | Service opportunity or job opportunity, according to the approved marketplace flow |
| Elite Professional Ledger | Not a BukieBrainJobs product name |

Agents must not copy legacy recruitment terminology into BukieBrainJobs interfaces merely because it appears in `DESIGN.md`.

## Locked BukieBrainJobs design direction

- Corporate Modern
- Premium Minimalism
- Deep Navy `#001A41` as the primary brand/action system
- Emerald `#296A4B` as strategic emphasis
- Hanken Grotesk for display and headings
- Inter for body and interface text
- 1280px maximum content container
- 24px standard desktop gutter
- Responsive 12/8/4-column grid model
- WCAG 2.2 AA baseline

## Conflict rule

If visual token information conflicts with an older technical example, use this canonical design direction and record the conflict in the decision log. Do not silently invent a replacement token.

If product language conflicts with `DESIGN.md`, the approved BukieBrainJobs product specification wins.

## Implementation rule

This document does not replace `DESIGN.md`. It defines the authority boundary required to prevent legacy source wording from being mistaken for current BukieBrainJobs product requirements.
